サブエージェントを複数起動すると、transcriptだけでは誰が何をしているのか追いかけにくくなります。そのため、エージェントツリーを横のパネルに描くModがいくつも出ています。7個を選んでリポジトリを取得し、フックモジュールを読みました。インストールや実行はしていません。

<Aside>
7個のうち[ide-mod](/ja/mods/ide-mod/)は、このサイトの運営者が作ったModです。他の6個と同じ項目を同じ方法で記載し、弱点もコードで確認したとおりに書いています。
</Aside>

基準: コミュニティカタログ 2026-10-04 スキャン、Claude Code 2.1.289。ソースは2026-10-06に読み、APIの説明はClaude Code 2.1.290の型ファイルで確認しました。ide-modは2026-10-06に初めて公開されたため、カタログにはありません。スター数はリポジトリ単位です。

## どれも同じ材料で描いています

7個すべてが、ごく少数のイベントでツリーを作っています。`agent.spawn` でエージェントが生まれ、`tool.call` の `agentId` で誰が今何をしているかが分かり、`turn.complete` や `turn.step` で終了とトークンが分かります。さらに `$.agent.list()` を定期的に呼んで状態を合わせています。

`$.agent.list()` だけでは足りません。型ファイルの説明によると、エンジンがタスクを片付けるとそのエージェントは一覧から消え、ワークフローのエージェントは最初から一覧に入りません。そのため、どのModもイベントで自分の状態を別に持っています。違いは、それ以外に何を追加で読み、何を追加で行うかにあります。

## Mod別メモ

### agent-flow

- `$` の呼び出しは、時計、ストア、画面、コマンド登録、`$.agent.list` だけです。ファイル・プロセス・モデル・ネットワークを使わないので、カタログでは0段階です。
- `classic.PermissionRequest` と権限通知を受け取り、権限確認を待っているエージェントを別に表示します。
- 2秒ごとの照合と1秒ごとの再描画のタイマーは、作業中のエージェントがいるときだけ動きます。
- 最初のサブエージェントが起動したとき、ターミナルが144桁以上あれば、パネルを一度だけ自動で開きます。人が閉じると、再び開くことはありません。

### agentpane

- エージェントを押すと、そのエージェントの会話を `$.session.messages({ agentId })` で読み、Claude Codeと同じ見た目で表示します。
- `turn.step` の使用量から、エージェント別のトークンと実際のモデル・effortを集計します。
- Stopを押してもう一度確認すると、`$.tool.call` で `TaskStop` を呼びます。カタログが2段階とした理由です。
- `$.agent.list` を、エージェントがいなくても1秒ごとに呼びます。最後のエージェントが終わって10秒後にパネルを折りたたみます。デスクトップアプリだけが接続している場合は、自動では開きません。

### cctop

- Modは画面を担当し、数値は別のRustプログラム `cctop` が作ります。Homebrewかcargoで別にインストールする必要があります。Modは `cctop query <項目> --session <id>` を実行してJSONを受け取ります。
- パネルが閉じているときはタイマーと実行が止まるとコメントに書かれていて、コードもそのとおりです。
- コーチ画面のボタンは、`$.prompt.fill` で入力欄にコマンドを埋めるだけで、送信はしません。
- すべてのフックに `.catch` が付いていて、失敗しても元の流れに戻します。
- バイナリはすべては読んでいません。Cargoの依存関係にHTTPクライアントがないことと、オプション機能のOpenTelemetryレシーバーが `127.0.0.1` にだけバインドされることまで確認しました。

### flightdeck

- フック15個のうち、自身のコマンドとパネル描画を除くすべてが観察のみです。`tool.check` で判定を読み、GATEパネルに許可・質問・拒否を積み上げ、判定はそのまま渡します。
- 正規表現(デフォルトは `advisor|architect`)に合うエージェントタイプをarchitectとして別にまとめ、いつ相談したかを表示します。
- `$.store`、ファイル、プロセスは使いません。セッションが終わると記録は消えます。
- デフォルトでは、セッション開始時にパネルを開きます。

### agent-shell-watch

- エージェントよりも、Bash呼び出しとバックグラウンドタスクが中心です。`codex`、`pi`、`devin` などの別のエージェントCLIをBashで起動すると、経過時間、出力が最後に変わった時刻、判定を表示します。
- 出力ファイルの末尾を `tail -c` で読みます。上限と使用量は、`~/.codex/sessions/` と `~/.pi/agent/sessions/` のセッションファイルから読みます。実行中のrunnerがあるか、そのビューを開いたときだけで、間隔は最短30秒です。
- テストファイルは30個で、7個の中で最多です。コードも最長です。

### mission-control

- メインターンにEdit・Writeがあると、ターン終了時にhaikuを `$.model.complete` で呼びます。編集内容の一部(Editは変更前後の文字列を各300文字、Writeは先頭400文字、ファイルあたり最大1,500文字)を送り、ファイルごとに1行の説明を受け取ります。パネルが閉じていても呼び、オフにするオプションはありません。
- コードマップはSVGを作り、ヘッドレスChromeでPNGを撮影します。Chromeのパスが `/Applications/Google Chrome.app/...` に固定されているため、macOS以外ではコードマップが描画されません。専用の一時プロファイルを使います。
- コードマップにimport関係を描くため、Claudeが触ったコードファイルを読み、先頭20万文字の中からimportを探します。

### ide-mod

- ボードの1行要約は、haikuを `$.model.complete` で呼びます。ボードが30秒以内に描画されたときだけ、20秒ごとに、一度に作業中のエージェント最大3個までです。役割、担当タスク、直近のツール呼び出し12個の1行要約を送ります。デフォルトはオンで、`s` でオフにでき、3回失敗すると自動でオフになります。
- HWP・PDFビューアは、`node` で `bin/` 以下のスクリプトを実行し、そのスクリプトが `pdftoppm`、`qlmanage`、`sips` を呼びます。このスクリプトは `$` の外で動くため、`claude plugin validate` の `calls:` 行やカタログのような静的スキャンでは内部の動作が見えません。直接読んだところ、ローカルでの変換だけで、ネットワーク呼び出しはありません。
- `open`、`qlmanage`、`sips` はmacOSのコマンドです。他のOSでは、プレビュー機能が動作しません。
- リクエスト履歴をセッションごとに `$.store` に残し、直近40セッションだけを保持します。韓国語の原稿ファイルを編集すると、文体チェックを実行します。画面の文言は韓国語のみです。
- フックモジュールが1ファイル1,493行で、6個のどのModよりも1ファイルに集中しています。

<Aside type="caution">
モデルを呼ぶダッシュボードは、mission-controlとide-modの2つです。どちらもセッションのアカウントでAnthropic APIを呼び、使用量に計上されます。送る内容には、ツール入力と編集したコードの一部が含まれます。
</Aside>

## どれを選ぶか

- 何も読まず、何も実行しないツリーが必要なら **agent-flow**。権限確認を待っているエージェントが別に表示されます。
- サブエージェントの会話をパネルの中で開いて確認し、止めたいなら **agentpane**。
- 権限判定、コンテキスト、相談の記録まで1画面で見たいが、保存は望まないなら **flightdeck**。
- コンテキスト・コスト・ツール時間をbtopのように深く見たく、別プログラムのインストールが問題ないなら **cctop**。
- CodexやPiのような別のCLIをBashで動かして作業を分担するなら **agent-shell-watch**。
- Claudeが触ったファイルとimport関係をマップで見たいmacOSユーザーは **mission-control**。編集のたびにhaikuが呼ばれる点は考慮してください。
- HWP・HWPX・PDFを同じウィンドウで見たく、韓国語の画面で問題ないなら **ide-mod**。macOSで最もよく動作します。

どのModでも、インストール前に[インストール前の安全チェック](/ja/guide/safety-checklist/)を通し、他の候補は[Modディレクトリ](/ja/mods/directory/)で探してください。
